# Read endpoints with no authorization guard beyond authentication and
# organization scoping.
#
# Half the reads in this API were in this state, which made the .view
# permissions decorative: an organization could not build a role that reads
# less than everything, because the permission it would withhold was never
# consulted. What is left is deliberate.
#
#   api/v1/auth/me, /branches, /organization, /module-access/{menu,modules,
#   organization-modules} - what the UI reads to render itself. Gating these
#   blanks the navigation for everyone.
#
#   api/v1/hr/me/*, /notifications*, /events* - the caller's own record.
#
#   api/v1/portal/* - the customer portal, which authenticates with its own
#   session token rather than a staff JWT.
#
#   api/v1/hr/directory, /hr/holidays, /trade/incoterms - who works here, when
#   the office is shut, and a published list of trade terms.
#
#   api/v1/sensitive/{type}/{id}/reveal - guarded by a step-up token from a
#   re-authentication, checked against the resource and audited. Stronger than
#   a permission, and not visible as middleware.
#
# A ratchet: adding a route here is how a new ungated read gets past the build.
